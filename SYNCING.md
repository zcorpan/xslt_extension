# Syncing with upstream and releasing to AMO

This repo is a Firefox fork of [mfreed7/xslt_extension](https://github.com/mfreed7/xslt_extension) (the Chrome extension). Upstream mostly bumps the `xslt_polyfill` submodule ([mfreed7/xslt_polyfill](https://github.com/mfreed7/xslt_polyfill)), regenerates `xslt-extension.js`, and bumps the version. This fork carries a few Firefox-only changes on top, which must survive every sync:

- `manifest.json`: the `browser_specific_settings` block (`gecko` and `gecko_android`: add-on ID `@xslt-polyfill.zcorpan`, `strict_min_version`, `data_collection_permissions`).
- `README.md`: Firefox/AMO wording and links.
- `BUILD.md`, `SYNCING.md`, `.gitignore`, `web-ext-config.mjs`.

Everything else (`content.js`, the `xslt_polyfill` submodule pin, `xslt-extension.js`, `SECURITY-REVIEW.md`, `test/`) should match upstream. The `version` in `manifest.json` matches upstream, except for Firefox-only releases between upstream versions, which add a fourth component (`1.0.25.1`) so the next upstream version (`1.0.26`) still sorts higher.

Don't publish until steps 2 and 3 pass. If the new upstream version fails them, ship the previous submodule pin, or fix it locally (e.g. an option in `content.js`'s `xsltPolyfillOptions`, then `node scripts/bundle.mjs`) and release a fourth-component version.

## 1. Merge upstream

Sync by merging, not rebasing, so `main` on `origin` never needs a force push.

```sh
git remote add upstream git@github.com:mfreed7/xslt_extension.git  # once
git checkout main
git pull origin main
git fetch upstream
git log --oneline main..upstream/main     # what's new upstream
git merge --no-ff --no-commit upstream/main
```

Expected conflicts and how to resolve them:

- `manifest.json` `version`: take upstream's value. Keep the `browser_specific_settings` block.
- `content.js`: take upstream's. Prefer upstreaming fixes as PRs to mfreed7/xslt_extension.
- `xslt-extension.js`: regenerate it with `node scripts/bundle.mjs`; with upstream's `content.js` and submodule pin it should match upstream's (step 2).

Then check that the only remaining differences from upstream are the Firefox-only changes listed above:

```sh
git add -A
git diff --cached upstream/main
git commit -m "Merge upstream/main (X.Y.Z)"
```

## 2. Verify the bundle

Upstream commits `xslt-extension.js`, generated by `scripts/bundle.mjs` from `content.js` and the `xslt_polyfill` submodule. `node scripts/bundle.mjs` also builds the Wasm module, which needs emscripten (not installed here), so check it without the build step. The polyfill repo commits its `xslt-polyfill.min.js`, so rebuilding the bundle from it must give the committed file:

```sh
git submodule update --init xslt_polyfill   # not recursive; the libxml2/libxslt submodules aren't needed
python3 -I - <<'EOF'
read = lambda f: open(f).read()
bundle = ("// Generated by scripts/bundle.mjs from content.js and xslt_polyfill/xslt-polyfill.min.js. Don't edit.\n(() => {\n"
          + read('content.js') + '\n' + read('xslt_polyfill/xslt-polyfill.min.js') + '\n})();\n')
print('IDENTICAL' if bundle == read('xslt-extension.js') else 'DIFFERENT')
EOF
```

That shows `xslt-extension.js` contains exactly those two files. That `xslt-polyfill.min.js` is built from the polyfill's source and the `dist/xslt-wasm.js` glue is upstream's to ensure; if in doubt, rebuild in the polyfill repo (needs emscripten) and compare.

## 3. Security review

Follow [SECURITY-REVIEW.md](SECURITY-REVIEW.md): the threat model, what to look for in `git diff OLD NEW -- src scripts Makefile` of the polyfill and in changes to `content.js` and `manifest.json`, and the tests. Run `test/active-firefox.py` and `test/security.html` with the built zip. Fork-specific notes:

- Anything that makes the polyfill run where it didn't before has to be undone locally (e.g. in `content.js`'s `xsltPolyfillOptions`, then regenerate the bundle) and released with a fourth-component version.
- Private reporting wasn't enabled on mfreed7/xslt_polyfill in October 2026; email the maintainer and ask for it rather than opening a public issue that describes an exploit.
- Known test results: `test/security.html` B1 fails (accepted risk, see SECURITY-REVIEW.md). A new failure, or B1 passing, is worth noting in the release notes.

## 4. Build, lint, and test

Requires [`web-ext`](https://github.com/mozilla/web-ext) (`npm install -g web-ext`). `web-ext-config.mjs` keeps `test/` and `scripts/` out of the package.

```sh
web-ext lint     # expect 0 errors and 0 warnings
web-ext build --overwrite-dest --artifacts-dir ../web-ext-artifacts
```

This produces `../web-ext-artifacts/xslt_polyfill-X.Y.Z.zip`. Load it in Firefox (`about:debugging` or `web-ext run`) and open a local XML file with an `<?xml-stylesheet type="text/xsl" href="...">` processing instruction, served over HTTP. While Firefox has native XSLT, Firefox itself does the transform and the console says the extension isn't running. The extension only transforms when native XSLT is missing. Also run section A of `test/security.html` with this build.

## 5. Push to GitHub

```sh
git push origin main
```

## 6. Submit to AMO

Listing: https://addons.mozilla.org/en-US/firefox/addon/xslt-polyfill/ (add-on ID `@xslt-polyfill.zcorpan`). AMO rejects a version number it has seen before, so `version` must be higher than the last submitted one.

Either upload the zip at https://addons.mozilla.org/en-US/developers/addon/xslt-polyfill/versions/submit/, or use `web-ext sign` with API credentials from https://addons.mozilla.org/en-US/developers/addon/api/key/:

```sh
WEB_EXT_API_KEY=... WEB_EXT_API_SECRET=... web-ext sign --channel=listed
```

On zcorpan's machine the keys are in the macOS Keychain (shared with zcorpan/github-merge-helper-ext, since AMO API keys are per account):

```sh
WEB_EXT_API_KEY="$(security find-generic-password -s github-merge-helper-amo -a jwt-issuer -w)" \
WEB_EXT_API_SECRET="$(security find-generic-password -s github-merge-helper-amo -a jwt-secret -w)" \
web-ext sign --channel=listed
```

This takes a few minutes (validation, then approval) and downloads the signed `.xpi` to `web-ext-artifacts/`.

`xslt-extension.js` contains the minified polyfill, so AMO may ask for source code. Point reviewers at the mfreed7/xslt_polyfill commit the submodule pins (build instructions in its README) and `scripts/bundle.mjs`.
